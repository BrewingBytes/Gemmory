## Problem

The daily play streak (#33) exists but is nearly invisible: a "4 days in a row" chip on the gallery tabs row from day 2, a 5-day gift wheel, 7/30-day achievements, and the evening reminder's streak reason. Nothing celebrates a new day, nothing shows history, and a broken streak just disappears. Day-1 ≥35% / day-7 ≥12% retention targets (`docs/designs/gemmory.md` Success Criteria) need a daily pull inside the app, not only the opt-in reminder.

## Scope

1. **Streak history (foundation).** `firstFinishedDay` only covers first finishes after T35 and no forgiven/frozen/repaired days are stored, so the calendar and week row need a day log: one entry per streak day with its kind (finished, day off, freeze, repaired). It lives in the "streak" store (backed up, no photo data; a restore can't add days). Pure codec + rules in commonMain. Backfill once from play files.
2. **Day-extended celebration.** When the player leaves the completion screen after a finish that started a new streak day (`PlayStreak.played()` returned a length), a full-screen moment shows the count rolling up (4 → 5), this week's row filling in, a sound and a haptic, and "Continue" plus "See your streak". If the day was saved by the day off or a freeze, it says so. The interstitial is skipped on that exit (ad rule: no stacked interruptions). Reduced motion: no roll-up, static number.
3. **Milestones.** 7, 30, 50, 100, 365: a bigger celebration and a gem tier (the streak's gem gains a facet or glow). Ties into the 7/30 achievements.
4. **Streak screen.** Opened from the chip (now tappable), the celebration and the nudge. Shows the big number + the streak gem, best streak, this week's row, a month calendar with each day's finished picture as a thumbnail (photo canvases included in-app), day-off status ("Your day off this week is ready"), freezes held, progress to the next gift (moved from the Inventory sheet or mirrored), and the repair offer when eligible. Broken state shows 0 and how to start again.
5. **Keep-it-alive nudge.** On the gallery, when the streak is ≥2 and nothing is finished today: "Finish a picture today to keep your 6 days", pointing at Today's picture if it's Quick and unfinished, else the closest-to-done canvas, else a Quick picture. Never on the canvas or the completion screen.
6. **Streak repair.** After a break, within 2 days, once per 30 days: a rewarded video from the streak screen (gallery side, so it fits the ad rules) restores the streak; free for VIP. No-fill / failure follows the existing rewarded-video rules.
7. **Earned streak freezes.** A new Inventory item, won on the gift wheel, held up to 2, auto-used after the weekly day off when a gap would break the streak. The evening reminder's "breaks at midnight" check (`shown(state, today + 1) == 0`) must count freezes.
8. **Home-screen widget.** Glance widget: the streak, whether today is done, tap → streak screen. Updates on finish and at local midnight. Never a photo (a home screen is public).
9. **Streak share card.** At milestones, a 9:16 card ("30 days of gems") through the existing share sheet. Never a photo canvas thumbnail.

Analytics: `streak_celebration_shown` (length, milestone, saved_by), `streak_screen_opened` (source), `streak_nudge_shown` / `_tapped`, `streak_repair_offered` / `_completed` (vip), `streak_freeze_earned` / `_used`, `streak_widget_added`, `streak_share_completed`.

## Flow

```
canvas finish ─► reveal ─► completion screen ─leave─► [new streak day?]
                                                   ├─ yes ─► celebration (milestone variant) ─► gallery (no interstitial)
                                                   │              └─ "See your streak" ─► streak screen
                                                   └─ no  ─► gallery (interstitial per caps)
gallery ─ chip / nudge ─► streak screen ─ repair (video | VIP free) ─► restored
widget ─tap─► streak screen
```

## Day resolution (pure, commonMain)

```
gap = today - lastDay
gap <= 0          → no change
gap == 1          → +1 (finished)
gap >= 2          → missed = gap - 1
                    cover with: weekly day off (if allowed) then freezes (held)
                    all missed covered → +1, log covered days as day off / freeze
                    else               → broken; repair offer open for 2 days
```

## Failure modes to cover

- Clock moved back or time-zone change: no change, no double celebration.
- Two finishes the same day: celebration once. A Play again finish counts as a finish (existing rule).
- Midnight passes on the completion screen: the day is the finish's day, not the exit's.
- Process death between finish and exit: the pending celebration must survive or be dropped on purpose (eng decision).
- Repair video no-fill / dismissed early: no repair, offer stays, no state change.
- Backup restore: history can't add days beyond the stored state.
- Widget stale after midnight: shows "not done today" via a midnight update.

## NOT in scope

- Changing what counts as a day (D2).
- Friends / leagues / social streaks (no backend for user content).

### 1. Architecture

**Day resolution (pure, commonMain, `DailyStreak`).** Covers missed days in this order: weekly day off (existing `restDay`), VIP weekly freeze (`vipFreezeDay`, VIP only, E6), inventory freezes (E5). Returns a `DayResult(length, keptBy, freezesUsed, coveredDays)`.

```
finish (PlayViewModel:96)
  └─► PlayStreak.played(vip, freezesHeld)
        ├─ DailyStreak.played(state, today, cover) ─► DayResult? (null: not a new day)
        ├─ save prefs: StreakState + pendingCelebration(day, length, keptBy)      [source of truth, E4]
        ├─ Inventory.spend(STREAK_FREEZE) × freezesUsed                          [after the save, E5]
        ├─ StreakHistory.append(day kinds, canvas ref)  (GMRS, display only)     [E4]
        ├─ analytics streak_day + onDay (gift spin, achievements)                [existing]
        └─ widget refresh                                                         [issue C]

gap = today - lastDay
  <= 0 → null
  == 1 → +1, keptBy=finish
  >= 2 → missed = gap-1; cover with day off → VIP freeze → freezes
         all covered → +1, keptBy=dayOff|freeze, log covered days
         else        → broken: length 1, brokenLength/brokenOn saved (repair window opens)
```

**Completion exit (MainActivity.kt:194-211, E3).**

```
leave fresh Completion
  ├─ pending celebration for today? ─yes─► push Route.StreakDay ─leave─► Gallery
  │                                         then the existing chain (O4):
  │                                         reward return → glint only; else reminder ask; else interstitial (caps)
  └─ no ─► existing chain (reward → ask → interstitial)
gallery visit with a pending celebration (process died on completion) → Route.StreakDay once, same day only (E2)
```
The `top == Route.Gallery` check becomes "the fresh completion was left, directly or through StreakDay"; the fresh tracker (`completion.fresh`) carries through StreakDay.

**Repair (issue B).** `StreakState` gains `brokenLength`, `brokenOn`, `lastRepairDay`. `repairOffer(state, today)`: broken, today - brokenOn <= 2, no repair in the last 30 days, brokenLength >= 2. `repair()` restores `brokenLength + 1`-style continuity: length = brokenLength, lastDay = today - 1 (finishing today extends it), missed days logged as "repaired". VIP: free; others: `RewardType.STREAK_REPAIR` video with grace (E8). Offered on the streak screen and as the nudge's broken variant, never on the canvas or completion screen.

**Reminder (finding 4).** `DailyStreak.shown(state, day, cover)` counts the day off, VIP freeze and freezes held; `ReminderReasons` gets `freezes` and `vip` in its inputs.
