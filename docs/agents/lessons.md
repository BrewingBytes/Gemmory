# Lessons

Gotchas learned while working on Gemmory, newest last. Add a dated line when a change teaches something the next session would otherwise relearn ([workflow.md](workflow.md) → Lessons). When a lesson becomes a rule, move it into workflow.md and delete it here.

## Emulator and connected tests

- 2026-10-15 (#5): a full `connectedDebugAndroidTest` timed out at 8 minutes when the host was out of RAM (16.7 of 18 GB swap), and one run ignored SIGTERM and needed `kill -9`. Running one class at a time (`timeout -k 15 360` each) on a cold-booted emulator with `-memory 4096 -no-snapshot` passed everything.
- 2026-10-15 (#5): `SheetAccessibilityChecksTest` is a second class inside `AccessibilityChecksTest.kt`, so a loop over test files misses it. List classes, not files.
- 2026-10-16 (#31): `adb shell` reads stdin. In a `while read … done < classes.txt` loop it swallows the rest of the list and only the first class runs. Give every adb call `< /dev/null`.
- 2026-10-16 (#31): at emulator load ~15-37, tests that wait for the gallery's starter tile (10 s) or for a canvas to open (5 s) time out, an instrumentation process can crash, and a cold launch can raise an ANR. CanvasAccessibilityTest, BillingFlowTest and HighlightStyleTest all passed once the load was below 3. Recheck on a quiet emulator before calling a timeout a regression.
- 2026-10-16 (#32): the app reads the ledger (allowance, grace, ad caps) into memory at startup, so deleting `ledger/` files in a connected test's `@Before` doesn't reset it. Call `GemmoryApp.resetMonetizationForTest(fakeAds)` after clearing them, and `resetMonetizationForTest()` in `@After` to put AdMob back. A fake `AdGateway` also skips the UMP form (`ensureConsent`).
- 2026-10-16 (#50): the `emulator` on this host's PATH is a shim that resolves `../emulator` against the current directory and fails ("Qt library not found"). Boot with `$ANDROID_HOME/emulator/emulator` (`~/Library/Android/sdk/emulator/emulator`).
- 2026-10-16 (#50): after repeated `wm size` / `wm density` / `font_scale` changes, the emulator's launcher can raise an ANR dialog that keeps window focus, and every launch wait then times out (the app's starter tile never shows). `adb shell dumpsys window | grep mCurrentFocus` shows "Application Not Responding: …nexuslauncher". Cold-reboot the emulator; retrying doesn't help.
- 2026-10-16 (#50): a walkthrough or connected test that leaves a fresh completion on real AdMob can get a test interstitial (`AdActivity`) over the app about 4 s after Done, depending on the ad caps left by earlier runs ("No compose hierarchies found"). Use a fake `AdGateway` through `GemmoryApp.resetMonetizationForTest(fake)`.
- 2026-10-16 (#40): for a by-hand check on the emulator, `adb shell monkey -p … -c android.intent.category.LAUNCHER 1` printed its args and launched nothing; `adb shell am start -W -n com.brewingbytes.gemmory/.MainActivity` works. `uiautomator dump` right after a launch or a screen change can return the previous screen ("null root node returned"); wait 2-3 s and dump again before reading it.
- 2026-10-18 (#54): on the emulator, `FrameMetrics.TOTAL_DURATION` includes the wait for vsync, so a frame drawn on time ends 0-0.6 ms past its `DEADLINE`, and a strict `TOTAL > DEADLINE` called 10-12% of a pinch phase missed with its slowest frame at 16.8 ms. `CanvasFrameTimingTest` allows 1 ms past the deadline. Its fit-zoom pan draws ~3 frames (nothing moves at fit) and `pinch ->48dp` 54-81 (it reaches the zoom cap early), so a per-phase frame minimum has to stay well below 60.
- 2026-10-18 (#54): an emulator started with `nohup … &` from one Bash tool call shut itself down cleanly ("Wait for emulator … to shutdown gracefully") several calls later, when a later command hit the tool timeout and was moved to the background. Start it with `setsid nohup … < /dev/null & disown` so it doesn't share the tool's process group.
- 2026-10-19 (#77): macOS has no `setsid`, so the 2026-10-18 boot line fails there ("command not found") and no emulator starts. Detach with `nohup perl -MPOSIX -e 'POSIX::setsid(); exec @ARGV' ~/Library/Android/sdk/emulator/emulator -avd … < /dev/null & disown`.
- 2026-10-19 (#77): a full per-class run on the Mac with swap nearly full (14 of 15 GB) failed 7 classes, all launch or encode timeouts plus one doubled billing acknowledge. Re-run alone on a fresh boot at load 3-10, all 7 passed. Re-run failed classes before calling them a regression.
- 2026-10-16 (#40): after a full per-class connected run, CanvasGesturesTest kept timing out in `open()` (5 s for the photo tile) even run alone at load ~3; logcat showed GC blocked ~2 s and class verification at ~60 bytecodes/s (host swap 14/15 GB). A cold reboot of the emulator made the class pass 12/12. When the same launch timeouts repeat after a long run, cold-reboot before re-running.

- 2026-10-16 (#35): a monitor built as `tail -f log | awk '… exit'` doesn't end when awk exits: `tail` only notices on its next write, and a finished run writes nothing more. Stop it by hand (TaskStop, then `pkill -f "tail -n +1 -f <log>"`).
- 2026-10-16 (#35): to see a milestone or any moment deep into a Big canvas by hand, seed the progress with a throwaway instrumented class that places gems through `PlaySession.place` and writes a 24dp `ViewState` centered on the next gem, then `adb shell input tap` the canvas center and `screenrecord` it (`ffmpeg -vf "fps=4,tile=6x2"` makes a frame sheet). Delete the class before the PR.
- 2026-10-16 (#57): booted without `-gpu`, gemmory_pixel picked software rendering (`gles_mode_selected:swangle`, SwiftShader in `/tmp/emu.log` and `dumpsys SurfaceFlinger | grep GLES`), and every screen drew at ~10 fps (gfxinfo p50 105ms, "Slow issue draw commands" on almost every frame). Boot with `-gpu host` for any frame-rate check; the log then names the Apple GPU.
- 2026-10-16 (#57): for a by-hand frame check of one moment, `dumpsys gfxinfo <pkg> reset` right before the `input tap` and `dumpsys gfxinfo <pkg>` after it, and measure the same moment on main's code too: the canvas-to-completion switch alone gives 8-11 janky frames on the emulator, with or without the celebration. `screenrecord` while measuring adds its own jank.
- 2026-10-17 (#36): `connectedDebugAndroidTest` uninstalls the app when it ends, so a throwaway seeding class run through Gradle leaves nothing to look at by hand. Install both APKs (`adb install -r` the debug and the androidTest APK) and run the seed with `adb shell am instrument -w -e class <seed class> com.brewingbytes.gemmory.test/androidx.test.runner.AndroidJUnitRunner`; the app and its data stay.
- 2026-10-17 (#36): to check a time-lapse's real frames, pull the MP4 from the app's cache (`adb exec-out run-as com.brewingbytes.gemmory cat cache/timelapse/<file>.mp4 > out.mp4`) and tile chosen frames with `ffmpeg -vf "select='eq(n\,0)+eq(n\,449)',scale=270:-1,tile=2x1" -frames:v 1 sheet.png`.
- 2026-10-17 (#33): to seed a SharedPreferences file for a by-hand look, write the XML on the host, `adb push` it to `/data/local/tmp/`, then `adb shell run-as com.brewingbytes.gemmory sh -c 'mkdir -p shared_prefs && cp /data/local/tmp/<name>.xml shared_prefs/'` with the app force-stopped (run-as can't read the host path, and a running app overwrites the file). The app reads it at its next start.

- 2026-10-17 (#34): Today's picture makes one locked picture open each day, picked by date, so a connected test that pins which pictures are locked (or the Pictures order) can fail on some days only. Call `app.resetTodaysForTest(enabled = false)` in its `@Before` and `resetTodaysForTest()` in `@After`, as LockedPicturesTest and StoreScreenshots do.
- 2026-10-17 (#20): a throwaway instrumented class that opens a screen with a Compose test rule and then sleeps, so you can drive the app from the host with `adb shell input`, doesn't work: while the rule is active the test clock drives recomposition, so taps land (and even place gems) but nothing on screen or in the semantics tree changes. Let the seed set things up and end (onStop writes the canvas and its view), then launch the app normally and drive it by hand. The fake billing backend lives in memory, so VIP for a by-hand check comes from the paywall's "Start VIP" in that same app process.
- 2026-10-17 (#38): a connected test that waits for `hasTestTag(…) and hasText(…)` must search the merged tree (the default). In the unmerged tree a button's text is on a child of the tagged node, so the match never comes and the wait times out. Use `useUnmergedTree = true` only for one-property matches on the node that holds them.
- 2026-10-17 (#43): `-Pandroid.testInstrumentationRunnerArguments.class=` with a wrong package (`app.InventoryFlowTest` for `ads.InventoryFlowTest`) doesn't fail the Gradle run: the result XML shows tests="1" failures="1" (the class wasn't found). Read the test names in the XML, not only the counts.
- 2026-10-17 (#43): a by-hand look at remote pictures needs a catalog signed with the production key, because debug builds trust only `RemoteKeys.PRODUCTION`. Run `publishRemotePicture` with the real key, copy `pictures/v1/*` out and delete it, then put the files in the app's `files/remote/` (`adb push` to `/data/local/tmp/`, then `run-as … cp`, app force-stopped). Add a "GMRR" `state` with a fresh `lastSuccessMillis` so the app doesn't check GitHub, and `firstSeen` = today for the "New" label (written by a throwaway jvmTest through `RemoteStateCodec`).
- 2026-10-18 (#29): the work moved to a Linux host (CachyOS). The SDK is `/opt/android-sdk`, owned by root with an `android-sdk` group; a login session older than the group membership can't write to it (no `sg` here), so installs and license acceptance go through the founder (`sudo …/cmdline-tools/latest/bin/sdkmanager`, now a wrapper around `android sdk`). Check RAM with `free -g`, not `sysctl vm.swapusage`. AVDs live in `~/.android/avd`. A `sudo sdkmanager` install can leave a package without the other-execute bit (`build-tools/36.0.0/aapt` was `-rwxrw-r--`): Gradle then logs "Cannot run program …/aapt: Permission denied" after a connected run while the results still pass; `sudo chmod -R o+rX` the package. The emulator is `/opt/android-sdk/emulator/emulator`; with `-gpu host` it renders on the RX 9070, boots in about a minute, and its load is low enough to run connected tests right after boot.
- 2026-10-18 (#49): gemmory_pixel is a `google_apis` image: Google Play services is there but its Play Games module isn't, and it can't download it ("No successful Zapp module downloads … Games.optional"). Once `PlayGamesSdk.initialize` runs, a Play Games task can wait with no result, and GmsClient logs `DeadObjectException` every 5 s. That's why every Play Games call has a timeout. A real sign-in or unlock needs a Play Store image or a phone with a tester account.
- 2026-10-18 (#49): a real Play Games check runs on `gemmory_play` (pixel_7, API 35 `google_apis_playstore`; the founder installs the image with sudo and `chmod -R o+rX` it). A new AVD has `hw.keyboard=no`, so the host keyboard can't type the Google sign-in: set `hw.keyboard=yes` in its `config.ini` and cold-boot. Install the upload-signed release APK (`assembleRelease`; its SHA-1 has a Play Games credential, the debug key doesn't), sign in with a Play Games tester account, and a progress share picked into Messages unlocks Work in Progress, visible in Settings → Achievements.
- 2026-10-18 (#49): Play Games stays off while `game_services_project_id` in `games-ids.xml` is blank, so an R8 smoke of the release build doesn't reach the SDK. To exercise it, put a placeholder id in temporarily (`123456789012`), build, install, open Settings → Achievements, then restore the file.
- 2026-10-20 (#78): a fresh `-memory 4096 -no-snapshot` boot sat at load ~60, then ~26 a few minutes later; the first `CollectionsFlowTest` run timed out everywhere. Wait (bounded) for load under ~5 before the first class.
- 2026-10-20 (#78): the completion screen's Done can miss a tap during its entrance; a test that taps it once and waits for the gallery stalls on the completion screen. Tap until the gallery shows (`CollectionsFlowTest.done()`).
- 2026-10-20 (#78): `RemotePictures.check()` that leaves one grid out ends INCOMPLETE and doesn't bump `updates`, so a showing gallery never reloads with the new catalog. A connected test that withholds a grid runs `app.remote.check(force = true)` before launching.
- 2026-10-20 (#78): on this Mac a full verification run with the emulator up filled the disk (3.9 GB free, swap 9.6/10 GB on the same volume): Gradle failed writing `last-build.bin` and every later tool call failed with ENOSPC, the Bash tool included, so the founder had to stop the emulator and delete `build/` by hand. Check `df -h /` before the full gradle command; with under ~4 GB, close the emulator first and run the command in two halves.
- 2026-10-20 (#81): with host swap at 10.4 of 11 GB, `CanvasFrameTimingTest` failed on the emulator for both main (12.7%, 5.6% missed) and the branch (8.5%, 9.0%), with the failing phases changing run to run. Measure main on the same emulator before calling a miss a regression; the A06 on Test Lab is the real check.
- 2026-10-22 (#132): a PR video of a flow the connected tests already drive: start `adb shell "screenrecord --time-limit 120 /sdcard/x.mp4" &`, run the class with `am instrument`, then `adb shell pkill -INT screenrecord` and pull it; `ffmpeg -ss <t> -frames:v 1` pulls a full-size still and `fps=8,scale=270:-1` + palettegen makes a GIF small enough to embed. `adb shell monkey -p … 1` didn't bring the app up after `pm clear` here; `am start -W -n com.brewingbytes.gemmory/.MainActivity` did.
- 2026-10-22 (#132): tests of the Today card or the Tomorrow line now need a finished canvas first (T45 DR4): call `app.seedFirstFinish()` (androidTest `gallery/FirstFinish.kt`) after clearing canvases. It finishes a small photo canvas through the store, so Pictures, today's pick and the streak are untouched.
- 2026-10-23 (#133): to finish a bundled picture fast by hand, read its `.gmrg` (24×32 starter: cells are one u8 slot each from byte 228, after the 6-byte envelope head, the u16 size fields and 27 bytes per color), write one `input tap x y` line per cell of a color, `adb push` the script and run it with `adb shell sh`: 142 taps took ~3 s, the tray moves to the next color by itself when one is done. At fit zoom a drag doesn't place gems, and a swipe that starts within ~60 px of the screen edge is Android's back gesture (it closed the canvas).
- 2026-10-23 (#133): Firebase Analytics events reach logcat with `adb shell setprop log.tag.FA VERBOSE` (`Logging event: origin=app,name=…,params=…`), which is enough to check an event chain without the console; DebugView also needs `setprop debug.firebase.analytics.app <package>` (reset it with `.none.`). `first_open` there carried `previous_first_open_count=5` on a reinstalled emulator: it re-fires on every reinstall. The perf build only sends with `-Pgemmory.firebaseInPerf=true`. gemmory_play's UMP treats the emulator as EEA, so `first_launch` waits for the consent form.
- 2026-10-23 (#137): the share landing opens a picture directly when it's ready at the gallery's first look (after consent), so on the emulator's fast connection a remote id, downloaded while the EEA consent form is up or within a second of it, opens directly and the late "· Open" offer never shows. To exercise or capture the offer, give `resetRemoteForTest` a source that answers the first fetch after ~2 s (`SharedLandingFlowTest`). By hand, `-Pgemmory.fakeReferrer='…&utm_content=<id>'` plus `pm clear` runs the real path, consent form included (gemmory_pixel shows the debug demo form; Consent is at 540,1692).
- 2026-10-23 (#145): `GLUtils.texImage2D` uploads a Bitmap premultiplied, so a layer with soft edges (a fade, text, the Play badge's corners) must blend with `GL_ONE, GL_ONE_MINUS_SRC_ALPHA` and a shader that multiplies the whole color by the opacity; `GL_SRC_ALPHA` darkens every half-transparent pixel twice. Opaque layers drawn with blending off come out bit-identical either way, which is why the founder clips' frames didn't move (R1 framemd5). Also, the end card's shadow lives in its own layer, so that layer goes under the picture, or it dims it.
- 2026-10-23 (#145): to capture before/after share videos without a main build, the branch's `ShareFrame.CLIP` path is main's player frame byte for byte (R1), so `ShareCaptures` (`-e deviceChecks true`) encodes "today" and "new" side by side into `getExternalFilesDir(null)/share-captures/`.

- 2026-10-24 (#135): copy tests run against the real `res/values/strings.xml` through `XmlStrings` (androidApp `src/test/.../copy/`): it parses the file from disk, maps `R.string` ids to names by reflection and formats with `java.util.Formatter`, so a JVM test pins the English with no Robolectric. It refuses strings it doesn't model (leading or trailing spaces, quoted strings): a space at either end goes in as ` `. A scripted edit can turn that ` ` into a real space (it happened once here); check the file after one.
- 2026-10-24 (#135): in `Configuration(...).apply { setLocale(locale) }`, `locale` is the Configuration's own deprecated field, not an outer property of the same name; the only hint is the deprecation warning. Copy the outer value to a local first.
- 2026-10-24 (#135): for an English pixel diff of two builds, `PixelPins` (androidTest `app/`) pins the day, an offline remote catalog and the demo-mode status bar, and each build's captures run on a clean install (uninstall both packages first). SystemUI's demo mode still differs between runs (repeated wifi icons, or the real clock in a later test), so diff below the status bar (the top 140 px on these displays) and say so.
- 2026-10-24 (#135): `PlayStreakTest.aBrokenStreakShowsNothing` fails on main too (0.8.3 (19), gemmory_pixel, run alone at load ~4): a 5-day streak last played 3 days ago still shows the chip. Compare with main before calling it a regression.

## CI

- 2026-10-16 (#11): Firebase Test Lab is deprecated and shuts down on 2027-09-30 (#55). Spark gives 5 physical-device runs a day and each phone in a matrix is one run (the pricing page doesn't say so). A second 3-phone matrix the same day was refused whole at validation with `TEST_QUOTA_EXCEEDED`: nothing ran, nothing was billed, and the project has no billing account. So it's one 3-phone run a day.
- 2026-10-16 (#11): the Test Lab catalog doesn't name chipsets, and a Pixel isn't a separate encoder family: Pixel 9 (Tensor G4) logged `c2.exynos.h264.encoder`, the same as the Exynos Galaxy A35. The smoke log line names each phone's codec; check it before trusting a pick.
- 2026-10-16 (#11): a workflow's "Run workflow" button (and `gh workflow run`) only exists once the file is on `main`. To try a new workflow from its branch, push a throwaway tag it triggers on (`v0.3.1-t11-smoke`) and delete it afterwards.
- 2026-10-18 (#54): in a workflow `run:` script, `"${var:-text with a 'quote}"` doesn't parse: bash treats a `'` inside `${…:-…}` as a quote even within double quotes ("unexpected EOF while looking for matching `''"). Keep apostrophes out of default values, and check every step with `bash -n` before pushing (extract them with `yaml.safe_load`).
- 2026-10-16 (#11): Gradle's `testInstrumentationRunnerArguments` (the `@PerfTest` exclusion) don't reach Test Lab, which runs the APKs directly. Pick classes with `--test-targets`, never a whole-package run.
- 2026-10-21 (#113): Play Games v2 merges `PlayGamesInitProvider`, which initializes the SDK at every process start from the `games.APP_ID` meta-data, so `BuildConfig.PLAY_GAMES=false` alone doesn't keep it off. Test Lab signs a Google account in by default, so automatic sign-in on a debug-signed build sometimes opened the translucent `GamesResolutionActivity` over `MainActivity`, and Compose tests failed with "No compose hierarchies found" (not every run: v0.5.0 passed). If a Test Lab test can't find the app's UI, grep its logcat for `ActivityTaskManager` starts from the app's pid.
- 2026-10-21 (#115): to see where a frame's RenderThread time goes, trace the frame test on the emulator: `adb shell 'perfetto --background -o /data/misc/perfetto-traces/x.pftrace -t 60s -b 64mb sched freq gfx view hwui input dalvik -a com.brewingbytes.gemmory'`, run the class, pull the file, and group RenderThread slices by name with trace_processor (`curl -sSLo trace_processor https://get.perfetto.dev/trace_processor`, `python3 -I ./trace_processor -q query.sql x.pftrace`). Skia's op slices (`AAConvexPathOp`, `TextureOp`, `Texture upload …`) show what each frame replays. Compose `drawPath` with anti-aliasing is re-tessellated on every frame of the window, even when its composable didn't change, so put static path art in an offscreen layer (`graphicsLayer(compositingStrategy = CompositingStrategy.Offscreen)`). The emulator's frame totals swing under host swap, but op counts and stage medians don't.

## Bundled pictures

- 2026-10-16 (#31): a grid's CRC32 is the last 4 bytes of its `.gmrg` file, big-endian (`tail -c 4 <file> | xxd -p`). `GridFile.crc32` returns the same value.
- 2026-10-16 (#31): scripted sourcing works from Wikimedia Commons (license in the API's `extmetadata.LicenseShortName`); Pexels, Pixabay and Unsplash search block scripts. Commons returns HTTP 429 when searches come back to back, so leave a few seconds between requests and honor `Retry-After`.
- 2026-10-16 (#31): free ChatGPT image generation makes a few images a day, so ask for a sheet of tiles. 1536×1024 in 4×2 gives 3:4 tiles, 1024×1536 in 2×4 gives 4:3 tiles, 1536×1024 in 3×2 gives squares. Find the white gutters with per-column and per-row brightness, cut with a 4 px inset, then freeze each tile.
- 2026-10-16 (#31): thumbnail cost grows with the catalog. On gemmory_pixel, rendering all 50 gallery thumbnails took 183 ms (33 ms for the earlier 7), measured by `GalleryLoadTimingTest`.
- 2026-10-16 (#31): an AI tile can carry a protected product shape without any logo (a Vespa-like scooter was dropped). Check AI tiles for recognizable designs, not just for text and brands.
- 2026-10-16 (#31): `open(p, "w").write(open(p).read() + …)` truncates the file before reading it and wiped PROVENANCE.md once. Read first, then write. `BundledPicturesTest.everyPictureHasAProvenanceRow` now catches a lost row.
- 2026-10-16 (#32): what's free is `BundledPictures.FREE`, and everything else is locked. A connected test or walkthrough that opens a picture outside that set must unlock it first (`app.monetization.unlocks.unlock(id)`) or run as VIP, or the tap opens the rewarded sheet instead of the canvas.
- 2026-10-20 (#85): `ImageIO.write(image, "jpg", file)` on a `TYPE_INT_ARGB` image (what `BundledGridTool` and `getSubimage` of a PNG sheet can give) writes nothing and returns `false`; JPEG has no alpha. Draw it into a `TYPE_INT_RGB` image first and check the return value, as `RemotePictureTool.writeJpeg` does.

## App code
- 2026-10-20 (#81): the README's `brave` for the icon renders is the macOS app binary here: `"/Applications/Brave Browser.app/Contents/MacOS/Brave Browser"` (it also renders an SVG directly, as `tools/store/icon.py`'s store icon does).

- 2026-10-18 (#49): JVM unit tests can't make an `Activity` (android.jar's stubs throw "Stub!") and there's no Robolectric here. Keep an SDK whose clients need an Activity behind a small session interface (`GamesBackend.session(activity)` → `GamesSession`) so the logic is tested with a fake session.
- 2026-10-18 (#49): don't hold the lock that guards a local file across a network call: a hung Play Games task held the ledger lock, so new unlocks couldn't be saved. Lock the file only for its reads and writes, and serialize the sends with a second lock.

- 2026-10-18 (#29): `./gradlew -q <task> 2>&1 | grep "^e: "` printed nothing when Gradle failed before compiling (SDK licenses not accepted), which reads like a clean build. Check for "BUILD FAILED" or the exit status, not just for compiler lines. Also in zsh, quote globs passed to tools (`grep --include="*.kt"`): unquoted, zsh fails with "no matches found" before grep runs.

- 2026-10-17 (#43): a JUnit 4 test written `fun x() = runBlocking { … }` whose last line returns a value (`assertIs`, say) isn't run: JUnit reports one `initializationError` ("Method x() should be void") for the whole class. Write `runBlocking<Unit> { … }`.
- 2026-10-17 (#43): a Gradle task whose arguments come from a script-level provider or lambda breaks the configuration cache ("cannot serialize Gradle script object references"). Build the list when the task is configured, from `providers.gradleProperty` and `providers.fileContents`, and pass it to `args(…)`, as `publishRemotePicture` does.

- 2026-10-16 (#50): the gallery's tiles are what it last read: `GalleryViewModel.refresh()` re-reads and re-renders every canvas asynchronously each time the Gallery shows, so for a moment after Done a just-finished canvas still looks unfinished. Anything that acts on a tap reads the canvas itself (`CanvasStore.isFinished`), not `Tile.done`.
- 2026-10-16 (#35): `clearAndSetSemantics {}` also drops semantics set after it in the same modifier chain, a `testTag` included, so `onAllNodes(hasTestTag(…))` never finds the node. Put the `testTag` before the clear.
- 2026-10-16 (#58): the Pictures order is set by `GalleryViewModel.refresh()` from the unlocks and entitlements it reads when it finishes, and the starter tile shows before that. A connected test that changes VIP (or unlocks) right after coming back to the gallery can have the order flip under `performScrollToNode`, which then scrolls to the end without finding the tile. Wait for the refreshed state (`GalleryViewModel.state`, e.g. the tile `started`) before changing them.
- 2026-10-21 (#101): `performClick()` on a node laid out below the screen does nothing and doesn't fail; the test then times out waiting for the next screen. The streak celebration's buttons sat under a scrolled column given `heightIn(min = maxHeight)`; keep a full-screen moment's buttons outside its scroll, at the bottom (`Column { Column(Modifier.weight(1f).verticalScroll(…)); buttons }`).
- 2026-10-21 (#101): `PlayStreak` used to keep its own `DayClock(System::currentTimeMillis)`, so `app.testNowMillis` didn't move the streak's day; it now uses `app.dayClock`. A connected test that finishes a picture and expects the gallery after Done must call `app.resetStreakForTest(celebrations = false)`, or a new streak day's celebration sits in between.
- 2026-10-20 (#76): Start over on a bundled or remote picture deletes its whole canvas directory (`CanvasStore.startOver`), unlike a photo canvas's `clearProgress`. A per-canvas file that must outlive a Start over (the `play` file's first finished day) has to be carried across by hand: the store copies the picture in again and rewrites it.
- 2026-10-20 (#76): `PlayViewModel` is activity-scoped (`viewModel()` in PlayScreen), so code that pops a `Route.Canvas` from outside the canvas's own back (a reminder tap) must call its `close()` first, or the session keeps running with nothing on screen.
